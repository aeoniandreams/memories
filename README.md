# memories — X 대화 백업 앱

X(트위터)에서 나눈 대화를 대화별로 카드에 저장하고, 로그인한 특정 인원끼리만 볼 수 있게 공유하는 개인용 웹앱입니다.
서버 코드 없이 정적 파일(HTML/CSS/JS) + Firebase(Auth, Firestore)로 동작하며, GitHub Pages에 그대로 올려서 씁니다.

## 1. Firebase 설정하기 (최초 1회)

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 새 프로젝트를 만듭니다. (Google 계정 필요, 무료 요금제로 충분)
2. 프로젝트 개요 화면에서 `</>` (웹 앱 추가) 아이콘을 클릭해 웹 앱을 등록합니다. 이름은 아무거나 괜찮습니다.
3. 등록 후 나오는 `firebaseConfig` 값을 복사해서, 이 저장소의 `js/firebase-config.js` 안의 값을 그대로 교체합니다.
4. 왼쪽 메뉴 **Authentication** → "시작하기" → 로그인 방법에서 **이메일/비밀번호**를 사용 설정합니다.
5. 같은 화면의 **Users(사용자)** 탭에서 "사용자 추가"로 로그인 계정을 만듭니다.
   - 나와 상대방이 같은 계정을 쓰려면 계정 1개만 만들어서 아이디/비번을 함께 공유하면 됩니다.
   - 각자 계정을 쓰려면 계정을 2개 만들어서 각자에게 하나씩 알려주면 됩니다.
   - 이메일 형식이 필요하지만, 실제로 받는 메일함일 필요는 없습니다 (로그인 인증 링크를 보내는 게 아니라 아이디/비번 조합으로만 로그인합니다).
6. 왼쪽 메뉴 **Firestore Database** → "데이터베이스 만들기" → 프로덕션 모드로 생성 (리전은 가까운 곳 아무거나).
7. 생성 후 **규칙(Rules)** 탭을 열고, 이 저장소의 `firestore.rules` 내용을 그대로 붙여넣은 뒤 게시(Publish)합니다.
   - 이렇게 하면 로그인하지 않은 사람은 데이터를 아예 읽을 수 없습니다 (프론트엔드 코드를 봐도 데이터 자체가 오지 않음).

## 2. GitHub Pages로 배포하기

1. 이 저장소를 GitHub에 푸시합니다 (이미 되어 있다면 생략).
2. 저장소 **Settings → Pages**에서 Source를 "Deploy from a branch"로 설정하고, 배포할 브랜치와 루트(`/`)를 선택합니다.
3. 잠시 후 `https://<계정명>.github.io/<저장소명>/` 주소로 접속하면 로그인 화면이 뜹니다.

## 3. 대화 백업하는 방법 (사용법)

### 3-1. 북마클릿 설치 (최초 1회)

배포된 사이트에서 `bookmarklet.html` 페이지로 들어가면 두 개의 버튼이 있습니다.
**① 캡처 시작**, **② 캡처 완료** 두 개를 각각 브라우저 북마크바로 드래그해서 등록하세요.

### 3-2. 대화 캡처하기 (매번)

1. X에서 백업하고 싶은 대화(스레드나 DM)를 엽니다.
2. 북마크바의 **① 캡처 시작**을 클릭합니다.
3. 대화 끝까지 천천히 스크롤합니다. (스크롤하는 동안 화면에 나타나는 트윗을 자동으로 계속 인식해서 쌓아둡니다 — X가 오래된 트윗을 화면에서 지워도, 이미 인식한 내용은 안전하게 남아있습니다)
4. 다 내렸으면 **② 캡처 완료**를 클릭합니다. 대화 내용이 클립보드에 복사됩니다.

### 3-3. 앱에 저장하기

1. memories 앱에서 로그인 후 **"＋ 새 대화 추가"**를 클릭합니다.
2. 텍스트 상자에 붙여넣기(Ctrl/Cmd+V) 후 **"불러오기"**를 클릭하면 메시지 목록이 편집 가능한 형태로 나타납니다.
3. 프로필 사진, 닉네임, 아이디, 날짜, 첨부 이미지 중 비어있거나 잘못 잡힌 항목이 있으면 직접 채우거나 고칩니다.
   - 프로필 사진/첨부 이미지는 이미지 URL을 입력하는 방식입니다. 첨부 이미지는 여러 개면 줄바꿈이나 쉼표로 구분해서 넣으면 됩니다.
   - 날짜는 `0000.00.00` 형식으로 입력해주세요.
4. 필요하면 **"＋ 메시지 직접 추가"**로 메시지를 수동으로 더 넣을 수도 있습니다.
5. **저장**을 누르면 홈 화면에 새 카드가 생깁니다.

카드는 홈 화면에서 **가장 첫 메시지(썸네일)의 작성일 기준 최신순**으로 정렬됩니다.
카드를 클릭하면 대화 전체를 트위터 스레드처럼 볼 수 있고, 상세 화면 상단의 "삭제"로 지울 수 있습니다.

## 4. 알아두면 좋은 점

- **프라이버시**: Firestore 보안 규칙으로 막혀 있어서, 로그인하지 않은 사람은 코드를 열어봐도 실제 대화 데이터를 받아올 수 없습니다. 로그인 계정을 아는 사람만 볼 수 있습니다.
- **여러 기기 동기화**: 데이터가 클라우드(Firestore)에 저장되므로, 같은 계정으로 로그인하면 어느 기기에서든 같은 카드가 보입니다.
- **X의 화면 구조 변경**: X가 페이지 구조를 바꾸면 북마클릿의 자동 인식이 일부 실패할 수 있습니다. 이 경우 "새 대화 추가" 화면에서 누락된 항목을 수동으로 채워 넣으면 됩니다.
- **이미지**: 프로필 사진과 트윗 첨부 이미지 모두 파일을 업로드하는 게 아니라 이미지 주소(URL)를 그대로 저장해서 불러오는 방식입니다. X의 이미지 주소는 보통 그대로 사용할 수 있습니다. 북마클릿이 트윗 안의 첨부 이미지도 자동으로 함께 캡처합니다.
- **북마클릿이 X에서 동작하는 원리**: X는 외부 도메인 스크립트를 페이지 안에서 불러오는 것(`<script src="...">`)을 보안 정책(CSP)으로 차단합니다. 그래서 `bookmarklet.html`은 캡처 코드 전체를 북마클릿 링크(`javascript:...`) 안에 직접 담아둡니다 — 클릭하면 외부 요청 없이 그 자리에서 바로 실행되는 방식이라 CSP에 걸리지 않습니다. 캡처 로직을 수정할 땐 `js/bookmarklet.js` 하나만 고치면, `bookmarklet.html`이 접속할 때마다 그 내용을 읽어서 자동으로 최신 북마클릿 링크를 만들어 줍니다.
