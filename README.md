# memories — X 대화 백업 앱

X(트위터)에서 나눈 대화를 대화별로 카드에 저장하고, 로그인한 특정 인원끼리만 볼 수 있게 공유하는 개인용 웹앱입니다.
서버 코드 없이 정적 파일(HTML/CSS/JS) + Firebase(Auth, Firestore)로 동작하며, GitHub Pages에 그대로 올려서 씁니다.

## 1. Firebase 설정하기 (최초 1회)

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 새 프로젝트를 만듭니다. (Google 계정 필요, 무료 요금제로 충분)
2. 프로젝트 개요 화면에서 `</>` (웹 앱 추가) 아이콘을 클릭해 웹 앱을 등록합니다. 이름은 아무거나 괜찮습니다.
3. 등록 후 나오는 `firebaseConfig` 값을 복사해서, 이 저장소의 `js/firebase-config.js` 안의 값을 그대로 교체합니다.
4. 왼쪽 메뉴 **Authentication** → "시작하기" → 로그인 방법에서 **이메일/비밀번호**를 사용 설정합니다.
5. 같은 화면의 **Users(사용자)** 탭에서 "사용자 추가"로 로그인 계정을 만듭니다.
   - 나와 상대방이 같은 계정을 쓰려면 계정 1개만 만들어서 아이디/비번을 함께 공유하면 됩니다.
   - 각자 계정을 쓰려면 계정을 2개 만들어서 각자에게 하나씩 알려주면 됩니다.
   - 이메일 형식이 필요하지만, 실제로 받는 메일함일 필요는 없습니다 (로그인 인증 링크를 보내는 게 아니라 아이디/비번 조합으로만 로그인합니다).
6. 왼쪽 메뉴 **Firestore Database** → "데이터베이스 만들기" → 프로덕션 모드로 생성 (리전은 가까운 곳 아무거나).
7. 생성 후 **규칙(Rules)** 탭을 열고, 이 저장소의 `firestore.rules` 내용을 그대로 붙여넣은 뒤 게시(Publish)합니다.
   - 이렇게 하면 로그인하지 않은 사람은 데이터를 아예 읽을 수 없습니다 (프론트엔드 코드를 봐도 데이터 자체가 오지 않음).
8. **관리자 이메일 설정 (백업 생성/수정/삭제를 본인 계정만 할 수 있게)** — 이미 `ae0niandreams@gmail.com`으로 설정되어 있습니다.
   - `js/app.js` 맨 위쪽의 `const ADMIN_EMAIL = "..."; // 관리자 이메일 입력란` 부분, `firestore.rules`의 같은 주석이 달린 부분 — 이 **두 곳**이 관리자 이메일이 들어가는 자리입니다.
   - 나중에 관리자 계정을 바꾸고 싶으면, `// 관리자 이메일 입력란` 주석이 달린 두 값을 **똑같이** 새 이메일로 바꾼 뒤, `firestore.rules`는 Firebase 콘솔의 규칙(Rules) 탭에 다시 붙여넣고 게시(Publish)까지 해야 적용됩니다.
   - 두 곳 다 바꿔야 하는 이유: `js/app.js` 쪽은 화면에서 버튼을 보여줄지 말지만 결정하고, 실제 쓰기 권한 통제는 `firestore.rules` 쪽이 합니다. 두 값이 다르면 화면엔 버튼이 보이는데 저장은 거부되는 식으로 어긋날 수 있어요.
   - 관리자가 아닌 계정(상대방 계정)은 카드 목록을 보고 상세 내용을 열람할 수는 있지만, "새 대화 추가"/"이어서 추가"/"삭제" 버튼 자체가 안 보입니다.

## 2. GitHub Pages로 배포하기

1. 이 저장소를 GitHub에 푸시합니다 (이미 되어 있다면 생략).
2. 저장소 **Settings → Pages**에서 Source를 "Deploy from a branch"로 설정하고, 배포할 브랜치와 루트(`/`)를 선택합니다.
3. 잠시 후 `https://<계정명>.github.io/<저장소명>/` 주소로 접속하면 로그인 화면이 뜹니다.

## 3. 대화 백업하는 방법 (사용법)

### 3-1. 북마클릿 설치 (최초 1회)

배포된 사이트에서 `bookmarklet.html` 페이지로 들어가면 두 개의 버튼이 있습니다.
**① 캡처 시작**, **② 캡처 완료** 두 개를 각각 브라우저 북마크바로 드래그해서 등록하세요.

### 3-2. 대화 캡처하기 (매번)

1. X에서 백업하고 싶은 대화(스레드나 DM)를 엽니다.
2. 북마크바의 **① 캡처 시작**을 클릭합니다.
3. 대화 끝까지 천천히 스크롤합니다. (스크롤하는 동안 화면에 나타나는 트윗을 자동으로 계속 인식해서 쌓아둡니다 — X가 오래된 트윗을 화면에서 지워도, 이미 인식한 내용은 안전하게 남아있습니다)
4. 다 내렸으면 **② 캡처 완료**를 클릭합니다. 대화 내용이 클립보드에 복사됩니다.

### 3-3. 앱에 저장하기

1. memories 앱에서 로그인 후 **"＋ 새 대화 추가"**를 클릭합니다.
2. 텍스트 상자에 붙여넣기(Ctrl/Cmd+V) 후 **"불러오기"**를 클릭하면 메시지 목록이 편집 가능한 형태로 나타납니다.
3. 프로필 사진, 닉네임, 아이디, 날짜, 첨부 이미지 중 비어있거나 잘못 잡힌 항목이 있으면 직접 채우거나 고칩니다.
   - 프로필 사진/첨부 이미지는 이미지 URL을 입력하는 방식입니다. 첨부 이미지는 여러 개면 줄바꿈이나 쉼표로 구분해서 넣으면 됩니다.
   - 날짜는 `0000.00.00.` 형식(끝에 온점 포함)으로 입력해주세요.
4. 필요하면 **"＋ 메시지 직접 추가"**로 메시지를 수동으로 더 넣을 수도 있습니다.
5. **저장**을 누르면 홈 화면에 새 카드가 생깁니다.

카드는 홈 화면에서 **가장 첫 메시지(썸네일)의 작성일 기준**으로 정렬됩니다. 화면 오른쪽 위의 **"최신순 ▾" / "오래된순 ▾" 버튼**을 눌러 정렬 방향을 바꿀 수 있고, 그 옆의 **태그 드롭다운**으로 특정 태그가 붙은 카드만 걸러볼 수 있어요.
카드를 클릭하면 대화 전체를 트위터 스레드처럼 볼 수 있고, 관리자 계정으로 로그인했다면 상세 화면 상단에서 "이어서 추가", "수정", "삭제"를 쓸 수 있습니다.

### 3-4. 이미 백업한 대화에 이어서 추가하기

같은 대화를 나중에 더 캡처했을 때, 새 카드를 따로 만들지 않고 기존 카드 뒤에 이어붙일 수 있습니다.
1. 이어붙이고 싶은 카드를 열고 **"＋ 이어서 추가"**를 클릭합니다.
2. 평소처럼 북마클릿으로 캡처한 내용을 붙여넣고 불러오기 → 확인 → 저장합니다.
3. 새로 불러온 메시지들이 기존 대화 맨 뒤에 이어서 저장됩니다 (카드의 썸네일이나 정렬 기준이 되는 첫 메시지는 바뀌지 않습니다).

겹쳐서 다시 캡처해도 안전합니다 — 북마클릿이 트윗마다 고유 ID를 같이 담아두기 때문에, 이미 저장되어 있는 트윗은 자동으로 걸러지고 새 트윗만 추가됩니다. (수동으로 직접 입력한 메시지처럼 고유 ID가 없는 경우엔 아이디/날짜/본문이 모두 같을 때만 중복으로 판단합니다.)

### 3-5. 이미 백업한 대화 수정하기

카드를 열고 **"수정"**을 클릭하면, 그 카드의 메시지가 전부 편집 화면에 불러와집니다. 내용을 고치거나 "이 메시지 삭제"로 지울 수 있고, 필요하면 북마클릿 내용을 추가로 붙여넣어 더 넣을 수도 있습니다. **저장을 누르면 그 카드의 메시지 전체가 지금 편집 화면에 있는 내용으로 교체됩니다** ("이어서 추가"와 달리 기존 내용에 이어붙이는 게 아니라 통째로 바뀝니다).

### 3-6. 태그로 분류하기

"새 대화 추가" / "이어서 추가" / "수정" 화면 위쪽에 태그를 추가·삭제하는 칸이 있습니다. 태그는 홈 화면에 뱃지 같은 걸로 표시되지 않고, **오직 정렬 버튼 옆 드롭다운으로 걸러보는 용도**로만 쓰입니다.

### 3-7. 트윗에 코멘트 남기기

카드 상세 화면에서 각 트윗 **왼쪽의 말풍선(+) 아이콘**을 누르면 그 트윗에 대한 코멘트를 작성할 수 있습니다. 이 기능은 "수정"과 완전히 분리되어 있어서, 관리자가 아닌 로그인 계정도 자신의 코멘트만큼은 자유롭게 쓰고 고칠 수 있습니다(트윗 본문/이미지/태그는 여전히 관리자만 고칠 수 있어요).

- 관리자가 아닌 계정이 남긴 코멘트는 항상 **wine(와인잔)** 아이콘으로 저장됩니다.
- 관리자가 남기는 코멘트는 작성 창에서 **message-circle / coffee** 두 아이콘 중 원하는 걸 골라 저장할 수 있습니다.
- 트윗에 코멘트가 달려 있으면, 그 트윗 **오른쪽에 말풍선 모양 버튼**이 생기고 눌러서 내용을 확인할 수 있습니다. 코멘트가 없는 트윗에는 이 버튼 자체가 보이지 않습니다.
- 코멘트는 카드 썸네일에는 나타나지 않고, 카드를 열어서 상세 화면을 봐야만 보입니다.
- 코멘트도 이미지 코멘트와 마찬가지로 배경 서식 없이 붙여넣을 수 있고, 글자색은 야간/기본 모드에 따라 자동으로 바뀝니다.

## 4. 알아두면 좋은 점

- **프라이버시**: Firestore 보안 규칙으로 막혀 있어서, 로그인하지 않은 사람은 코드를 열어봐도 실제 대화 데이터를 받아올 수 없습니다. 로그인 계정을 아는 사람만 볼 수 있습니다.
- **여러 기기 동기화**: 데이터가 클라우드(Firestore)에 저장되므로, 같은 계정으로 로그인하면 어느 기기에서든 같은 카드가 보입니다.
- **X의 화면 구조 변경**: X가 페이지 구조를 바꾸면 북마클릿의 자동 인식이 일부 실패할 수 있습니다. 이 경우 "새 대화 추가" 화면에서 누락된 항목을 수동으로 채워 넣으면 됩니다.
- **폰트**: 본문 폰트(Pretendard JP)는 외부 CDN이 아니라 이 저장소의 `fonts/` 폴더 안에 직접 들어있습니다 (`css/fonts.css`가 그걸 불러옵니다). 일부 모바일 환경(데이터 절약 모드, 특정 CDN을 막는 DNS/네트워크 필터 등)에서 외부 CDN 폰트 요청이 막혀 특정 굵기만 시스템 기본 폰트로 보이는 문제가 있어서, 같은 사이트 안(1st-party)에서 직접 서빙하도록 바꿨습니다. 굵기를 추가하려면 [pretendard-jp](https://github.com/orioncactus/pretendard)에서 `.woff2` 파일을 받아 `fonts/`에 넣고, `css/fonts.css`에 `@font-face`를 하나 추가하면 됩니다.
- **이미지**: 프로필 사진과 트윗 첨부 이미지 모두 파일을 업로드하는 게 아니라 이미지 주소(URL)를 그대로 저장해서 불러오는 방식입니다. X의 이미지 주소는 보통 그대로 사용할 수 있습니다. 북마클릿이 트윗 안의 첨부 이미지도 자동으로 함께 캡처합니다.
- **북마클릿이 X에서 동작하는 원리**: X는 외부 도메인 스크립트를 페이지 안에서 불러오는 것(`<script src="...">`)을 보안 정책(CSP)으로 차단합니다. 그래서 `bookmarklet.html`은 캡처 코드 전체를 북마클릿 링크(`javascript:...`) 안에 직접 담아둡니다 — 클릭하면 외부 요청 없이 그 자리에서 바로 실행되는 방식이라 CSP에 걸리지 않습니다. 캡처 로직을 수정할 땐 `js/bookmarklet.js` 하나만 고치면, `bookmarklet.html`이 접속할 때마다 그 내용을 읽어서 자동으로 최신 북마클릿 링크를 만들어 줍니다.
- **캐시 무효화(cache busting)**: `index.html`에서 `css/style.css`, `css/fonts.css`, `js/app.js`를 불러올 때 뒤에 `?v=숫자`가 붙어 있습니다. 브라우저나 GitHub Pages의 CDN이 예전 파일을 한동안 그대로 캐시해서, 방금 배포한 CSS/JS 수정이 실제 기기에는 바로 반영되지 않는 경우가 있었습니다. 이 파일들 중 하나를 고칠 때마다 `index.html`에서 그 파일의 `?v=` 숫자를 하나 올려주면, 그 즉시 새 파일을 새로 받아오도록 강제할 수 있습니다.
